HP / Agilent 3458A REV9 firmware osszeallitasi es feltarasi terv

Kiindulasi adatok
- CPU: MC68HC000PB / Motorola 68000 csalad, big-endian vegrehajtasi modell.
- Feltoltott REV9 fajlok: U110...U115, mindegyik 65536 byte.
- Feltoltott REV7 referencia: 6 darabos U110...U115 es egy darabos 512 KiB image.
- A REV7 referencia alapjan a 6 darabos image helyes osszefuzese ellenorizheto volt.

Osszeillesztesi eredmeny
- U110 + U111 -> ROM bank 0, byte-interleave.
- U112 + U113 -> ROM bank 1, byte-interleave.
- U114 + U115 -> ROM bank 2, byte-interleave.
- Bankok sorrendje: bank0, bank1, bank2.
- Aktiv tartalom merete: 3 x 128 KiB = 384 KiB.
- 512 KiB egyfajlos formatumhoz a fennmarado 128 KiB 0xFF padding.
- REV7 ellenorzes: 6 darabbol osszerakott 384 KiB == egyfajlos REV7 elso 384 KiB: True.
- REV7 egyfajlos maradek 128 KiB csak 0xFF: True.

Melyik fajl mire valo?
- HP3458A_REV9_interleaved_raw_384K_from_U110-U115.bin: a hat REV9 EPROM aktiv 384 KiB-os, paronkent osszefuzott tartalma. Ez felel meg leginkabb az adott 6 EPROM-os hardver aktiv ROM-teruletenek.
- HP3458A_REV9_interleaved_raw_512K_padded_FF.bin: ugyanaz, de 512 KiB-ra 0xFF-fel kitoltve. Ez a REV7 egyfajlos referenciahoz hasonlo formatum.
- HP3458A_REV9_cpu_order_384K_for_Ghidra.bin: 16 bites byte-swappelt, 68000 disassemblyhez ajanlott aktiv image.
- HP3458A_REV9_cpu_order_512K_for_Ghidra_padded_FF.bin: disassemblyhez swappelt, 512 KiB-ra padolt valtozat.
- Bank fajlok: bankonkenti 128 KiB raw es CPU-order valtozatok, ha kulon ROM bankokat akarsz vizsgalni.

Fontos byte-sorrend
- A fizikai/programozo szerinti interleave image onmagaban meg nem a legjobb disassemblyhez.
- MC68HC000/68000 big-endian CPU elemzeshez 16 bites byte-swap kell az interleavelt image-en.
- Ghidra/IDA elemzeshez ezt hasznald: HP3458A_REV9_cpu_order_384K_for_Ghidra.bin
- 512 KiB padded valtozatot akkor hasznald, ha egy M27C4002-szeru egyfajlos/programozo-formatum kell.

Reset vector a REV9 CPU-order image elejen
- Initial SP: 0x0001897E
- Reset PC:  0x00000808
- Javasolt Ghidra import: Motorola 68000, big-endian, base address 0x000000, entry/reset PC 0x00000808.

Parancs / szerviz iranyu kovetkeztetes
- A firmware-ben megtalalhatoak a memoria-hozzaferesi parancsokra utalo stringek: MREAD, MWRITE, MADDR.
- Ez megerositi, hogy a WinGPIB-s CAL/NVRAM dump valoszinuleg a muszer sajat firmware parancsparseren keresztul hivott memoriaolvasasara epul.
- Kovetkezo reverse engineering cel: MREAD es MWRITE handler rutinok teljes visszafejtese, kulonosen a cimkonverzio, jogosultsag/protect ellenorzes es valaszformatum miatt.

Feladatterv
1. Archivum es integritas
   - Minden eredeti U110...U115 fajlt valtozatlanul tarts meg.
   - Minden uj image-rol SHA256 hash keszuljon.
   - A muszerben levo chipek helyet fotozd, hogy az U110...U115 pozicio kesobb ne keveredjen.

2. Firmware image eloallitasa
   - U110/U111, U112/U113, U114/U115 parok byte-interleave.
   - A 3 bank egymas utan.
   - Disassemblyhez 16 bites byte-swap.
   - Programozo/egyfajlos formatumhoz 512 KiB-ra 0xFF padding.

3. Ghidra projekt
   - Import: HP3458A_REV9_cpu_order_384K_for_Ghidra.bin.
   - Processor: Motorola 68000 big-endian.
   - Base: 0x000000.
   - Reset vector: PC=0x00000808.
   - Indulj a reset vektortol, majd nevezd el a megtalalt stringeket es parancstablat.

4. Command table feltaras
   - Keresd: MREAD, MWRITE, MADDR, CALLARRAY, CAL?, CALNUM?, REV?.
   - A stringek kornyezeteben azonositsd a rekordformatumot: string pointer / handler pointer / flag / parameter informacio.
   - A gyanus handler cimeket nevezd el: cmd_MREAD, cmd_MWRITE, cmd_MADDR.

5. MREAD/MWRITE funkcionalis visszafejtes
   - Deritsd ki, hogy a parameter decimalis vagy hex cimet var-e.
   - Deritsd ki, hogy byte, word vagy long read tortenik-e.
   - Deritsd ki, hogyan formatumozza a valaszt GPIB-re.
   - MWRITE esetben eloszor csak statikus elemzes: protect flag, CAL kapcsolo, unlock szekvencia, write-enable vonal. Vak probalgatas tilos.

6. CAL/NVRAM terulet azonositas
   - MREAD-del csak olvasasi teszt: ismert CAL RAM cimtartomanyok dumpja.
   - Hasonlitsd ossze a GPIB dumpot a fizikai DS1220/FRAM dumpal.
   - Endian, szavas/byte-os sorrend, offset es padding validalas.
   - Minimum 3 egyezo dump kell, mielott barmilyen irasi muveleten gondolkodsz.

7. Differencialis elemzes
   - Dump alapallapotban.
   - Egy nem kritikus front-panel setting valtoztatasa, majd uj dump.
   - Kulonbsegekbol meghatarozhato settings/NVRAM terulet, checksum es counter.
   - CAL konstansokhoz csak akkor nyulj, ha van teljes fizikai mentes es visszaallithato FRAM/chip.

8. Biztonsagi szabalyok
   - MREAD biztonsagosabb, MWRITE destruktiv lehet.
   - Kerulendo ismeretlenul: MWRITE, CAL, STORE, SAVE, INIT, ERASE, FORMAT.
   - Barmilyen iras elott: fizikai NVRAM backup, GPIB backup, hash, verify, es eredeti chip felreteve.

Mit tudunk most biztosan vagy nagy valoszinuseggel
- A REV9 hat EPROM-ja a REV7 referencia alapjan osszeallithato.
- Az aktiv firmware tartalom 384 KiB.
- Az egyfajlos 512 KiB formatum utolso 128 KiB-ja padding lehet.
- A CPU-order image reset vektora ertelmes 68000 vektorokat ad.
- A firmware tartalmaz MREAD/MWRITE/MADDR stringeket, tehat a memoriaolvaso/iro parancsok firmware-szinten jelen vannak.
- A pontos MWRITE biztonsagi feltetelek es a CAL RAM checksum/logika meg visszafejtesre var.
